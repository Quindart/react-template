# Login Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Xây dựng login demo, lưu phiên, bảo vệ Home và kiểm tra đầy đủ UX bằng Playwright.

**Architecture:** Giữ React Router Framework SSR. Auth nằm trong feature riêng, custom hooks điều phối form/store/navigation; Zustand persist lưu user, provider chung quản lý thông báo và khôi phục phiên. Route modules ghép các thành phần, không truyền auth qua nhiều tầng props.

**Tech Stack:** React 19, React Router 8 hiện có, TypeScript, Tailwind 4, shadcn/ui, Lucide React, React Hook Form, Zod, Zustand, Notistack, Vitest, Testing Library, Playwright, Prettier, ESLint.

**Spec:** `docs/superpowers/specs/2026-10-03-login-design.md`

## Global Constraints

- Tài khoản demo cố định: username `admin`, password `admin123456Aa@`.
- Zustand persist dùng localStorage với key `auth-session`, version `1`, chỉ lưu user `{ username: "admin" }` hoặc `null`.
- Giữ cấu hình SSR hiện tại. Không truy cập localStorage trong quá trình render server.
- Đăng nhập đúng luôn chuyển tới `/home`. Đăng xuất xóa phiên và chuyển tới `/login`.
- Không thêm thời gian chờ giả. Không dùng `waitForTimeout` để đồng bộ test.
- Copy tiếng Việt, thông báo và thời gian snackbar lấy nguyên văn từ spec; góc trên bên phải, tối đa hai thông báo.
- Đọc `~/.codex/RTK.md`, chạy shell qua RTK. Giữ nguyên thay đổi người dùng; `pnpm-lock.yaml` hiện chưa tracked, không ghi đè bằng lockfile khác.
- Chỉ tài liệu đã được thay đổi ở giai đoạn lập kế hoạch. Kiểm tra skill worktree khi bắt đầu thực thi, không tạo worktree trong bước này.

## Review Focus

- Username có khoảng trắng và password có khoảng trắng: chỉ trim username; Task 1 kiểm tra chính xác.
- Persisted payload có field lạ/version lạ: không nhập actions hoặc trạng thái hydration vào store; Task 1 kiểm tra merge theo allowlist.
- Mount lại provider/StrictMode: khôi phục phiên không chạy đua và không lặp snackbar; Task 2 kiểm tra.
- Store thành công trước khi chuyển trang: guest guard không được tháo form pending hoặc lặp redirect; Task 2 và 3 kiểm tra.
- Storage lỗi khi logout: UI phải xóa phiên bộ nhớ, báo rõ không thể xóa dữ liệu lưu nếu thao tác thất bại; Task 1 và 3 kiểm tra. Không hứa xóa được dữ liệu khi trình duyệt từ chối mọi thao tác ghi/xóa.

## Task 1: Schema, credentials và persisted session

**Files:** Create `app/features/auth/login-schema.ts`, `auth-service.ts`, `auth-store.ts`, `auth-storage.ts`, `auth-messages.ts` trong cùng thư mục; tests `tests/unit/auth.test.ts`, `tests/unit/auth-store.test.ts`; create `vitest.config.ts`, `tests/setup.ts`; modify `package.json`, `pnpm-lock.yaml`, `.gitignore`.

**Interfaces:**

- `loginSchema`, `LoginValues = { username: string; password: string }`.
- `authenticate(values: LoginValues): Promise<AuthUser | null>`, `AuthUser = { username: "admin" }`; resolved null cho credentials sai, không delay giả.
- `createAuthStore(storage: StateStorage)` tạo store độc lập để kiểm thử; `useAuthStore` là hook dùng trong ứng dụng.
- State: `user: AuthUser | null`, `hydrated: boolean`, `storageError: boolean`; actions `signIn(user): { persisted: boolean }`, `signOut(): { persisted: boolean }`, `hydrate(): Promise<void>`.
- `createSafeStorage(getStorage: () => Storage)` trì hoãn truy cập browser storage, theo dõi lỗi đọc/ghi; fallback bộ nhớ cho phiên hiện tại. Lỗi ghi không làm mất phiên vừa đăng nhập.
- `AUTH_MESSAGES` chứa các thông điệp đúng nguyên văn spec, dùng chung UI và hook.

- [ ] Cài dependencies auth và Vitest/Testing Library/jsdom bằng pnpm; chọn phiên bản tương thích peer dependencies hiện tại, không nâng React Router ngoài phạm vi. Script `test` = `vitest run`; chỉ include unit/hook tests, loại trừ E2E.
- [ ] Viết test schema/service trước implementation, gồm các assertions:

```ts
expect(loginSchema.safeParse({ username: '', password: '' }).success).toBe(
  false,
);
expect(loginSchema.parse({ username: ' admin ', password: 'x ' })).toEqual({
  username: 'admin',
  password: 'x ',
});
expect(
  await authenticate({ username: 'admin', password: 'admin123456Aa@' }),
).toEqual({ username: 'admin' });
expect(
  await authenticate({ username: 'admin', password: 'admin123456Aa@ ' }),
).toBeNull();
expect(
  await authenticate({ username: 'Admin', password: 'admin123456Aa@' }),
).toBeNull();
```

- [ ] Chạy `rtk pnpm test tests/unit/auth.test.ts`, xác nhận đỏ vì chưa có implementation; viết schema và service, chạy lại đạt.
- [ ] Viết tests store: signIn → raw JSON đúng `{ state: { user: { username: "admin" } }, version: 1 }`; store mới hydrate giữ user; signOut → reload user null. JSON hỏng, version lạ, user khác admin đều kết thúc hydrate với user null; extra fields không được merge. Storage throw vẫn signIn bộ nhớ, trả persisted false; signOut luôn xóa user bộ nhớ.
- [ ] Chạy `rtk pnpm test tests/unit/auth-store.test.ts`, xác nhận đỏ; triển khai Zustand persist với `skipHydration`, partialize user, merge allowlist và hydrate idempotent, kết thúc cả khi lỗi. Chạy lại đạt.
- [ ] Commit riêng các file Task 1 sau khi test đạt.

## Task 2: Login hook, provider và phản hồi hành động

**Files:** Create `app/features/auth/use-login.ts`, `use-logout.ts`, `session-bootstrap.tsx`, `login-progress.tsx`; create `app/providers/app-providers.tsx`, `tests/unit/use-login.test.tsx`, `tests/unit/session-bootstrap.test.tsx`.

**Interfaces:**

- `useLogin()` trả `{ form, onSubmit, phase, errorMessage, retryHome }`; `phase: "idle" | "submitting" | "redirecting"`; `form` là React Hook Form typed theo LoginValues.
- `useLogout()` trả `{ logout, isPending }`.
- `AppProviders({ children }: { children: ReactNode })` chứa SnackbarProvider và SessionBootstrap. SessionBootstrap gọi hydrate phía client, không gate toàn bộ cây theo user.
- `LoginProgress({ phase })` hiển thị status và progress theo spec; idle không render progress.

- [ ] Viết test hook với service/navigation mock có promise điều khiển: invalid form không gọi authenticate; credentials sai giữ username, clear/focus password và trả idle; đúng credentials signIn một lần, snackbar success một lần, navigate `/home` replace. Pending navigation giữ phase redirecting; reject service trả error chung; reject navigation giữ user và cho retryHome; persisted false dùng warning thay success.
- [ ] Thêm test submit lặp khi promise chưa resolve: `expect(authenticate).toHaveBeenCalledTimes(1)`. Test sửa field xóa lỗi credentials, submit lại thành công. Chạy `rtk pnpm test tests/unit/use-login.test.tsx`, xác nhận đỏ.
- [ ] Cài React Hook Form resolver và Notistack; triển khai hook theo interfaces Task 1. Dùng khóa đồng bộ tránh double submit, phân loại catch xác thực và navigation; không reset pending trước khi navigation hoàn tất. Đảm bảo focus password sau khi field được mở lại.
- [ ] Viết test bootstrap chạy dưới StrictMode: hydrate hoàn tất và không lặp notification. Triển khai provider với anchor top-right, maxSnack 2, preventDuplicate, nút đóng accessible; success 4000ms, error/warning 6000ms. Logout ghi user null, xóa bộ nhớ kể cả storage lỗi và thông báo đúng trường hợp.
- [ ] Triển khai LoginProgress indeterminate, label “Đang đăng nhập”, không `aria-valuenow` giả; status polite, giảm animation khi reduced motion. Chạy tests Task 2 đạt, commit file liên quan.

## Task 3: shadcn login, routing và Playwright

**Files:** Create `components.json`, `app/lib/utils.ts`, `app/components/ui/{button,input,label,card}.tsx`, `app/features/auth/{login-form,auth-gate}.tsx`, `app/routes/{login,index}.tsx`, `playwright.config.ts`, `tests/e2e/{auth,auth-pending}.spec.ts`, `tests/e2e/fixtures.ts`; modify `app/routes/home.tsx`, `app/root.tsx`, `app/routes.ts`, `app/app.css`, `package.json`, `pnpm-lock.yaml`, `.gitignore`.

**Interfaces:**

- `LoginForm()` dùng useLogin, chứa fields/toggle password/progress; không nhận auth qua props.
- `AuthGate({ children }: { children: ReactNode })` chỉ cho user đã hydrate xem Home; khách redirect replace. Guest redirect trong Login route phải phân biệt phiên khôi phục với login submit đang chuyển trang để không làm biến mất progress hoặc lặp navigation.
- Route index `/` → quyết định theo phiên; `/login` → Login; `/home` → AuthGate + Home. Retry navigation giữ UI có thể phục hồi hoặc ErrorBoundary có nút thử mở Home.

- [ ] Đọc docs cài sẵn đúng phiên bản React Router về routing/pending/rendering trước khi sửa routes. Lấy template và primitive shadcn/ui từ nguồn chính thức; giữ Tailwind 4 và alias `~/`, cài Lucide và dependencies primitive cần thiết. Không dùng bản giả chỉ đặt tên shadcn.
- [ ] Cài Playwright; cấu hình Chromium desktop và mobile viewport. `webServer` chạy `pnpm start` trên port test riêng với build có sẵn; CI không reuse server. Scripts `test:e2e` và `test:e2e:ui`; trace retain-on-failure, screenshot only-on-failure, HTML reporter.
- [ ] Viết E2E trước UI: form invalid, wrong username/password, success, persist JSON chính xác, refresh/tab mới, `/` và `/home` guest, `/login` authenticated, logout/Back, storage hỏng/bị chặn, password toggle/Enter, snackbar close/position, mobile overflow và hydration. Dùng fixture collect pageerror và hydration console errors, assertion cuối test là mảng rỗng.
- [ ] Chạy build rồi `rtk pnpm test:e2e tests/e2e/auth.spec.ts`, xác nhận test đỏ vì chưa có form/route; không coi lỗi cài browser/server là red test hợp lệ.
- [ ] Triển khai giao diện card sáng, desktop có phần giới thiệu, mobile một cột; labels tiếng Việt, autocomplete, aria-invalid/describedby, focus visible, icon trang trí aria-hidden. Form tự sở hữu toggle, hook sở hữu handler; không thêm chức năng ngoài spec. Root dùng `lang="vi"` và AppProviders; giữ ErrorBoundary hữu ích.
- [ ] Triển khai routes và hydration gate theo interfaces. Home hiển thị admin và nút logout, không render nội dung trước khi phiên được khôi phục. Bổ sung lỗi tải route với đường phục hồi Home.
- [ ] Viết test pending chặn request module Home trong browser bằng route interception và promise gate, giữ request tới khi assertions hoàn tất. Tắt prefetch tới Home nếu cần để test điều khiển request; không thêm delay hoặc test flag vào sản phẩm. Assert progress visible, form khóa, chỉ một success notification; release request và assert URL/Home. Nếu Framework bundle tải sẵn module, điều khiển route discovery request thực tế hoặc chuyển kiểm tra phase sang hook test và ghi rõ giới hạn E2E, không giả request không tồn tại.
- [ ] Build rồi chạy toàn bộ E2E desktop/mobile và unit tests; xem screenshot trên desktop/mobile, sửa lỗi quan sát được. Kiểm tra storage errors không khiến auth guard redirect vô hạn. Commit file Task 3 sau khi đạt.
